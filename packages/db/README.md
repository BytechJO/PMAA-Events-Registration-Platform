# @pmaa/db

PostgreSQL schema (Drizzle), migrations and the transaction + audit + outbox pattern.

| Path | What |
|---|---|
| `src/schema.ts` | Every table, enum, constraint and index (spec §12) |
| `drizzle/` | Migrations, applied in order by `pnpm db:migrate`. Generated by `pnpm db:generate`, except `0002_seed_roles.sql` (hand-written) |
| `rollback/` | Developer-only scripts that undo a migration (Drizzle has no down migrations) |
| `src/patterns.ts` | `inTransaction`, `recordAudit`, `enqueueOutbox` |

## Change the schema

1. Edit `src/schema.ts`.
2. `pnpm db:generate` writes a new SQL file in `drizzle/`. Read it, then commit it with the schema change.
3. `pnpm db:migrate` applies it to `DATABASE_URL`.
4. Add tests in `src/*.int.test.ts` for any new constraint.

## Roll back in dev

Never on staging or production. To undo the core tables (migrations 0001 and 0002):

```
psql "$DATABASE_URL" -f packages/db/rollback/0001_core_tables.sql
pnpm db:migrate    # applies them again
```

## Tests

`*.int.test.ts` run against a real PostgreSQL at `TEST_DATABASE_URL`. They skip when it is not set, except in CI, where `REQUIRE_DB_TESTS=1` makes them required. Test files run one at a time (`vitest.config.ts`) because they share that database. The migration tests create and drop their own throwaway databases.
